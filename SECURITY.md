# Security Policy

## Supported line

Security fixes are applied to the current maintained release line.

## Reporting a vulnerability

Do not report suspected vulnerabilities, credentials, private keys, customer data, or exploit details in a public issue.

Use GitHub's private vulnerability-reporting / Security Advisory flow for this repository when available. If private reporting is not available, contact the repository maintainer privately through GitHub before disclosure.

Include the affected version or commit, a minimal reproduction, expected impact, and any suggested mitigation.

## Scope

Security reports may cover the reference implementation, contract validation, integrity checks, authority/delegation handling, cryptographic use, or cases where conformance could be confused with execution authorization.

A conformance result is never itself permission to execute.
